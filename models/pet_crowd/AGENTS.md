# crowd-counter
Type: code

- Mission: count people in aerial/dense crowd photos (fine-tuned PET point-localization model, per-head dot overlay + total).
- Runtime: HF Space (Gradio SDK 6.19.0, Python 3.12, ZeroGPU); `origin` = https://huggingface.co/spaces/broyang/CrowdCounter, deploy = `git push origin main`. Local CPU run: `./setup_local.sh` then `./venv/bin/python count.py <image>`.
- URLs: https://crowd.skyebrowse.com (CNAME → hf.space) · app.skyebrowse.com/crowd-counter (iframe of https://crowd.skyebrowse.com, route in skyebrowse-web `HUGGINGFACE_ROUTES.crowdCounter`).
- Structure: `app.py` (UI + ZeroGPU handler), `count.py` (model build/inference/tiling/overlay), `PET/` (patched model code), `weights/` (git-lfs).
- Rules: this Space is Gradio 6 — `theme`/`css`/`js`/`head` go on `demo.launch()`, NOT `gr.Blocks()` (Gradio 6 moved them). UI must mirror the sibling Spaces' design language (interior-ai-designer is the reference): Markdown hero "# 👥 ... by [SkyeBrowse]", sponsor banner, inter-app nav cluster, forceLight JS, link-rewrite JS, JSON-LD + canonical head, SEO footer.
- ZeroGPU reservation (2026-09-11): `crowd_gpu_duration` uses 4 seconds for images with longest side ≤1280 and shortest side ≤768; larger images retain 7 seconds. Inference budget is duration minus 0.5 seconds. The large-image allowance preserves the July two-grid accuracy fix; do not globally lower it. HF may multiply the declared duration by its node duration factor.
- The Space self-restarts after one hour of container uptime, matching 3D AI and Anime AI; the external five-minute watchdog still handles `RUNTIME_ERROR` when the container cannot run its own restart thread.
- Always LIGHT mode on every host (Bobby 2026-07-02): enforced by the `_force_light_theme` FastAPI middleware (307 `/` → `/?__theme=light` for Accept: text/html; relative Location; probes get 200). Gradio 6's CSR frontend does NOT execute `launch(js=...)`/`head=` scripts, so the sibling-style client-side redirect never runs — do not rely on custom_js for anything load-bearing in this repo.
- Embedding is restricted through the `Content-Security-Policy: frame-ancestors` response header in `_force_light_theme`: `https://skyebrowse.com`, `https://*.skyebrowse.com`, plus `http://localhost:8080` for local webapp development.
- Successful user uploads save the original and first counted overlay to the configured Google Drive folder through `drive_storage.py`; threshold recounts and bundled examples do not create duplicate Drive files. Drive saving is asynchronous and best-effort so storage failures never break inference.

## Accuracy protocol (2026-07-03, validated on 3 Edgewater July-4 drone stills + stadium example)
- Inference = two shifted tile grids (second offset by stride/2) unioned, then score-ranked dedup with adaptive radius (0.45× each point's 4th-NN distance, clipped [1.5, 4]px). +10–26% recall vs single grid, placement quality unchanged (4104→4498, 2837→3224, 757→955; stadium example 1394→1345 after true-dupe removal).
- `PET/models/pet.py` `test_forward` patched to return `sparse_keep_counts`/`dense_keep_counts` (splits flattened points per tile). PET inference is batch-size-1 ONLY — `points_queris_embed_inference` v_idx indexing breaks at B>1; do not batch tiles.
- Candidate caching (2026-09-11): `predict_candidates_tiled` collects points/scores at threshold 0.1 once per image; `filter_predictions` applies the requested threshold BEFORE adaptive deduplication. `gr.State` isolates one cached image per session (3600-second TTL), keyed by decoded pixel hash + shape; clear/upload changes invalidate it. Never reuse threshold-filtered or already-deduplicated points as the candidate cache. Recounts/examples still skip Drive storage. Local model parity passed at thresholds 0.1/0.35/0.5/0.9.
- `predict_candidates_tiled(time_budget=…)` skips grid B when grid A used >45% of budget. Large-image budget remains 6.5 seconds; small-image budget is 3.5. The fallback still returns grid A candidates with the same deduplication.
- Do NOT: global upscale (2× helps dim sparse regions but −40% on small blurry heads + FPs on textured blankets; 3× collapses to near-zero), tile >768 (quadtree splitter false-positive explosion: img1 4104→7822 phantom), CLAHE/gamma/sharpen preprocessing (all reduce recall; gamma 0.6 on the night shot: 757→8).
- Known FP: red/white/blue patterned table runners counted as heads (~1% of total on July-4 field shots). Known misses: dim shadowed street/queue crowds partially detected; night oblique high-altitude shots remain a large systematic undercount (model floor, not config — treat those counts as lower bounds).
- Local venv gotcha: Python 3.9 pulls torch 2.2.2, which needs `numpy<2` + `opencv-python-headless==4.10.0.84` (setup_local.sh's unpinned install grabs numpy 2 and breaks torch↔numpy interop). MPS == CPU results, ~2× faster.

## Known failure modes
- **crowd.skyebrowse.com showed a login form / "TypeError: Load failed" (resolved 2026-07-02).** The custom-domain proxy forwards `x-forwarded-host` but not `x-forwarded-proto`, so Gradio computed `root_url = http://crowd.skyebrowse.com` and the https page mixed-content-blocked every fetch; Gradio 6 SSR then rendered its login-form fallback (SSR also dropped `launch(head=...)` meta entirely). Fix, both required: `ssr_mode=False` in `launch()` + the `_https_get_root_url` monkeypatch in app.py (upgrades http→https for non-localhost hosts, because CSR still server-renders `theme.css`/`iframeResizer` URLs from the computed root). Do not remove either when upgrading Gradio; re-verify https://crowd.skyebrowse.com in a browser after any Gradio bump.
- **HEIC (iPhone) uploads crashed with `PIL.UnidentifiedImageError` in Gradio preprocessing (resolved 2026-08-04, commit ab675ad).** Gradio's `image_utils.preprocess_image` calls `PIL.Image.open` even with `type="filepath"`, and stock Pillow has no HEIC decoder. Fix: `pillow-heif` in requirements.txt + `register_heif_opener()` at import time in app.py (registers globally in PIL). Verified via live-Space API call with a real .heic.

- Browser failure diagnosis (2026-09-11): the native queue SSE returned `You have exceeded your ZeroGPU runs limit.`; the later HF `by-subdomain` 401 was a secondary status lookup, not proof that counting requires public source. Capture SSE errors before diagnosing from HTTP errors alone. Authenticated counting passed (stadium 1,345 people, 4.66s; cached recount 1.10s). Preserve `gr.Error` text in the count field so quota rejection is visible instead of generic Error; keep prior cached candidates on rejection. Protected visibility was requested through HF settings; anonymous app/config stayed accessible and source stayed inaccessible. No reset time or numerical run cap was provided by HF.
